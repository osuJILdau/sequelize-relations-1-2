# Практическая работа №1.2 — Связи таблиц

Консольное приложение на Node.js с Sequelize и SQLite. В базе две таблицы: **авторы** (`authors`) и **книги** (`books`). У одного автора может быть несколько книг — связь **1:N**.

## Запуск

Нужен установленный Node.js.

```bash
npm install
npm start
```

После запуска программа создаёт таблицы, добавляет авторов и книги и выводит их в консоль. База находится в файле `database.sqlite` и не загружается на GitHub. При каждом запуске таблицы создаются заново через `sync({ force: true })`.

## Структура

- `db.js` — подключение SQLite.
- `models/Author.js` — модель автора (`name`, `country`).
- `models/Book.js` — модель книги (`title`, `year`, `genre`).
- `models/relations.js` — связи `hasMany` и `belongsTo` по `authorId`.
- `index.js` — создание записей, получение всех авторов с книгами через `include` и вывод.

В программе используется метод `author.createBook()`, который появляется благодаря связи `hasMany`.

## Пример вывода

```text
Автор: Лев Толстой (Россия)
  - Война и мир, 1869, Роман
  - Анна Каренина, 1877, Роман
Автор: Антон Чехов (Россия)
  - Чайка, 1896, Пьеса
```

## Ответы на вопросы

1. **Почему связи задают с двух сторон?** Чтобы получать данные и методы связи как от автора к книгам, так и от книги к автору.
2. **Где находится внешний ключ при `belongsTo`?** В таблице, которая принадлежит другой. Здесь это `books.authorId`.
3. **Какие методы даёт `hasMany`?** Например, `getBooks()`, `addBook()`, `createBook()`, `countBooks()`.
4. **Зачем `as`?** Оно задаёт имя связи. В `include` нужно указать тот же псевдоним.
5. **Чем `hasOne` отличается от `belongsTo`?** При `hasOne` внешний ключ находится в дочерней модели, при `belongsTo` — в модели, где вызвали `belongsTo`.
6. **Что будет без `through` у `belongsToMany`?** Sequelize выдаст ошибку, потому что для такой связи нужна промежуточная таблица.
